# LoyaltyLoop

Gamified loyalty points for **HighLevel (GoHighLevel)**, built to be installed from the **App Marketplace**
on many sub-accounts at once. Each location has its own rules, balances, tiers and activity log.

**What it does**

- Earn points for: paid invoices (× multiplier, optional minimum), appointment status (showed / confirmed),
  new contacts, or a tag being applied.
- Redeem by tag (e.g. `redeem_coffee`): deducts points, removes the tag, **refuses if the balance is too low**.
- VIP tiers: tags a contact the first time they reach a threshold (default `VIP_Gold` @ 1000).
- Balance is mirrored to a contact custom field (`contact.loyalty_points_balance`) for workflows, smart lists and merge fields.
- Dashboard embedded in the CRM (Overview, Rules, Members search + manual adjust, Activity, Settings).
- Workflow webhook so any automation can earn/burn points (per-location API key, idempotency keys).
- Public pages: Home, Docs, Support, Privacy Policy, Terms (contact: idylle_radieuse@outlook.com, IR Official).

## What changed from the sample you shared

| Sample | Now |
|---|---|
| Any browser could read/write any location's rules via `/api/loyalty/:locationId` | Dashboard calls are authenticated with a **signed session token minted from the encrypted HighLevel SSO payload**; the location comes from the token, never from the URL |
| `?locationId=` URL bypass in production | Removed (dev-only flag, ignored in production) |
| Used `data.locationId` from the SSO payload | Uses `activeLocation` (what HighLevel actually sends); agency view without a location is handled |
| Webhooks unauthenticated | **Ed25519 `X-GHL-Signature` verified** over the raw body (legacy RSA `X-WH-Signature` optional) |
| Whole DB in one Redis JSON blob, read-modify-write races | Per-location keys; balances in a Redis sorted set with **atomic** adjust (Lua) |
| Points = read contact → add → write (races, double counting on every "contact updated") | Ledger is the source of truth; **idempotent** per webhook, invoice, appointment, tag and contact; mirrored to the CRM field |
| Tokens stored in plain JSON | Tokens **AES-256-GCM encrypted** at rest; refresh uses single-flight + Redis lock (refresh tokens rotate) |
| `innerHTML` with rule data (XSS) | DOM built with `textContent`; strict CSP (no inline scripts) |
| No uninstall handling | `AppUninstall` deletes all data for the location; `AppInstall` mints tokens for bulk/future installs |

## Run locally

```bash
npm install
cp .env.example .env        # fill in values (see below)
npm run dev                 # http://localhost:3000
npm test                    # 21 end-to-end tests, no network needed
```

Local dashboard without HighLevel: set `ALLOW_DEV_LOCATION=true` and open
`http://localhost:3000/app?dev=<locationId>` (the location must exist from a real install). Ignored when `NODE_ENV=production`.

To receive real webhooks/OAuth locally, tunnel with ngrok/cloudflared and set `APP_BASE_URL` to the tunnel URL.

## Configure your HighLevel Marketplace app

Developer portal -> **My Apps** -> your app. Replace `https://YOUR_DOMAIN` with your deployed `APP_BASE_URL`.
(Menu labels in the portal change occasionally; the values are what matter.)

1. **Auth (Advanced Settings -> Auth)**
   - **Redirect URL:** `https://YOUR_DOMAIN/oauth/callback/lc`
   - **Scopes** (enable all): `contacts.readonly` `contacts.write` `locations.readonly` `locations/customFields.readonly`
     `locations/customFields.write` `invoices.readonly` `calendars/events.readonly` `oauth.readonly` `oauth.write`
   - Copy **Client ID**, **Client Secret** and **Shared Secret** -> `GHL_CLIENT_ID`, `GHL_CLIENT_SECRET`, `GHL_SHARED_SECRET`.
   - Copy the **App ID** -> `GHL_APP_ID`.
2. **Distribution:** *Sub-account & Agency* (so agencies can bulk install).
3. **Custom Page (the dashboard):** add a Custom Page / Custom Menu Link in the sub-account sidebar with URL
   **`https://YOUR_DOMAIN/app`**. HighLevel loads it in an iframe and the page asks the parent for the encrypted user
   context (SSO). `/app` sends `frame-ancestors *` so it also works on white-label domains.
4. **Webhooks (Advanced Settings -> Webhooks):** URL **`https://YOUR_DOMAIN/webhook/leadconnector`**, events:
   `AppInstall`, `AppUninstall`, `ContactCreate`, `ContactTagUpdate`, `InvoicePaid`, `AppointmentCreate`, `AppointmentUpdate`.
5. **Listing URLs:** Support `/support` · Privacy `/privacy` · Terms `/terms` · Docs `/docs` · Website `/`.
6. **Install link:** `https://YOUR_DOMAIN/install` redirects to the Marketplace chooser (built from `GHL_CLIENT_ID`).
   If you prefer, paste the app's own install link into `GHL_INSTALL_URL`.

## Environment variables

See `.env.example` for everything. Required in production:

| Variable | Purpose |
|---|---|
| `GHL_CLIENT_ID`, `GHL_CLIENT_SECRET` | OAuth |
| `GHL_SHARED_SECRET` | Decrypt the in-CRM SSO payload (dashboard sign-in) |
| `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` | Persistent storage (free at upstash.com). Vercel's Upstash integration's `KV_REST_API_*` also work |
| `TOKEN_ENC_KEY` | 32-byte hex key encrypting OAuth tokens at rest. **Never change it** after install |
| `SESSION_SECRET` | Signs dashboard sessions |
| `APP_BASE_URL` | Public URL (auto-detected on Vercel/Render) |
| `GHL_APP_ID` | Lists sub-accounts after an agency install (recommended) |

`GET /health` shows what is configured and lists warnings (no secrets are exposed).

## Deploy

### Vercel
1. Push this folder to GitHub -> **Import** in Vercel (framework: *Other*, no build command, output directory empty).
2. Add the env vars above (or add the **Upstash Redis** integration from the Vercel Marketplace, which injects `KV_REST_API_*`).
3. Deploy, then set `APP_BASE_URL` to your production URL and redeploy.
4. `vercel.json` already rewrites `/api`, `/webhook`, `/oauth`, `/sso`, `/install`, `/app`, `/health` to the function; static pages are served from `public/`.

### Render
1. **New -> Blueprint** and pick the repo (uses `render.yaml`), or create a *Web Service* manually: build `npm ci --omit=dev`, start `node server.js`, health check `/health`.
2. Fill in the env vars (`TOKEN_ENC_KEY`/`SESSION_SECRET` are generated for you).
3. Use a **paid instance**: free instances spin down and webhooks sent while asleep will be slow.

### AWS
See [`docs/aws.md`](docs/aws.md): App Runner (simplest), Elastic Beanstalk, or ECS Fargate + ALB. A `Dockerfile` is included.

## How it works

- **Install:** `/oauth/callback/lc` exchanges the code. *Location* installs store that location's tokens. *Company*
  (agency) installs store the agency token and mint a token per approved sub-account via `/oauth/location-token`;
  any sub-account that isn't minted yet is connected on first open (the SSO payload tells us the agency + location),
  and `AppInstall` webhooks cover "install to future locations". Each new location gets default rules, tiers, a
  workflow key and the *Loyalty Points Balance* custom field.
- **Dashboard auth:** `/app` -> `postMessage(REQUEST_USER_DATA)` -> HighLevel replies with an encrypted blob ->
  `POST /sso/session` decrypts it with the Shared Secret, verifies the location is installed and returns an 8-hour
  signed token. Every `/api/*` call is scoped to the location inside that token. The token is invalid the moment
  the app is uninstalled.
- **Events:** `POST /webhook/leadconnector` verifies the signature, normalises the payload (flat or `{type, data}`
  envelopes), claims the delivery once, evaluates your rules, adjusts the ledger atomically, then mirrors the
  balance/tags to HighLevel. If HighLevel is unreachable, points are kept and the contact is queued for **Sync now**.
- **Data keys (per location):** `ll:<loc>:rules|settings|bal|activity|stats|awards|names|dirty`, plus
  `ll:install:<loc>` (encrypted tokens) and `ll:company:<id>`.

## Verification and known limits

- **Verified here:** 21 automated end-to-end tests against a *simulated* HighLevel (OAuth, token refresh, SSO,
  signature checks, every rule type, idempotency, redeem refusal, tiers, CRM failure + resync, reinstall seeding,
  uninstall cleanup, security headers) plus a headless-DOM smoke test of the dashboard.
- **Not verified here:** a live HighLevel account. Payload shapes follow HighLevel's published webhook docs, and the
  normaliser accepts several variants, but do a real test install and watch the first webhooks (`Activity` tab, server
  logs). The things most worth confirming on a live account: the SSO payload field `activeLocation`, the
  `InvoicePaid` payload carrying `altId`/`contactDetails.id`, and the `approvedLocations` shape for agency installs.
- Refunds / voided invoices don't reverse points automatically (use **Members -> Adjust**). Only fully paid invoices earn.
- Per-instance rate limiting only (a brake, not a firewall) - put Cloudflare/AWS WAF in front if you expect abuse.
- Storage uses Upstash's REST API; ElastiCache would need an extra driver (see `docs/aws.md`).
- Legal pages are solid starting points, not legal advice - have them reviewed. The support page promises a reply
  "within two business days"; change it in `scripts/build-pages.js` if that's not your SLA.
